# 插件开发

## 1. 目标

插件优先解决扩展问题，不要把主流程改成依赖覆盖核心文件。

## 2. 基本结构

- `conf.json`
- `install.php`
- `uninstall.php`
- `setting.php`
- `hook/`
- `static/` 或模板资源

## 3. 开发规则

- 插件视为受信代码，但仍要保持最小改动面
- 优先用 hook、设置页、独立资源
- 不引用公共 CDN
- 不把一次性迁移写回核心安装脚本

## 4. 安装与卸载

- 安装脚本负责初始化自己的表、配置和默认数据
- 卸载脚本负责清理自己的 KV、数据表或临时资源
- 存量库需要补结构时，提供独立迁移说明

## 5. 后台设置页

- 写操作保持管理员会话、`safe_token` 和审计日志
- 回显内容按上下文转义
- 页面结构复用现有后台容器，不自带整页壳

## 6. 数据访问

- SQL 优先走 `db_table()`、`RepositoryFactory`、`QueryBuilder`
- 避免循环查库和 `SELECT *`
- 新增索引、表结构时说明升级路径

## 7. 发布前检查

- `php -l` 通过
- 安装、启用、停用、卸载至少跑一遍
- hook 生效、设置页可保存、日志无明显异常
- 插件包中不包含点文件、软链、本地环境文件
