# Docker 部署与任务队列

默认执行 `docker compose up -d --build`，启动 app、db 和独立 worker。
worker 每两秒启动一次 CLI 单批消费者，普通页面仅入队，不再执行采集。
非 Docker 环境需通过计划任务定期执行 `php tools/queue_worker.php --limit=1`，
或由进程管理器循环调用。CLI 消费者每批重新加载配置，避免常驻配置过期。
后台任务页仍可手动执行队列。

视频和文章采集取页失败时，队列重试最多三次后标记失败；空列表且合法的
pagecount=0 视为正常无更新。手动分页接口保留原有错误展示。

Docker 中程序代码归 root 所有，PHP 用户仅能写 data、runtime、upload、
plugins、template。在线升级不能改写核心文件，核心升级应重建镜像。
安装配置写入 data，不要求 core/config 可写。

模板和插件使用独立命名卷，重建容器会保留安装内容。升级内置模板或插件时，
需要另外备份并更新对应卷内的文件，镜像中的新副本不会覆盖已有卷。
从旧版容器升级前，应先备份其 template 和 plugins 中的自定义内容并迁入新卷；
命名卷首次初始化只能复制新镜像内置内容，无法找回已删除旧容器中的自定义文件。
不要使用 `docker compose down -v` 升级，避免删除数据库和站点数据。

启动脚本通过 Git 属性和镜像内换行规范化兼容 Windows 检出。PHP 8.5 已内置
OPcache 时跳过重复安装，较早的基础镜像仍按需编译。
