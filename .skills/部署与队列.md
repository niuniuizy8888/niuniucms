# Docker 部署与任务队列

默认执行 `docker compose up -d --build`，启动 app、db 和独立 worker。
worker 每两秒启动一次 CLI 单批消费者，普通页面仅入队，不再执行采集。
宝塔等单站环境在采集页或任务管理页复制 curl 命令，粘贴到「计划任务 → Shell 脚本」。
无需知道 PHP 可执行文件或站点目录，也不要求额外配置 worker。
生成的命令使用双引号参数，兼容部分宝塔版本为非 root 执行用户添加的单引号包装。
已有单引号命令在 `www` 用户下报 `no URL specified` 时，请重新复制更新后的命令替换；无需改用 root。
新入口 `api.php?route=collect&code=来源编码&h=24` 使用请求头令牌鉴权，创建或继续指定来源任务，
每个请求处理一页并保存断点，通过本站相对 302 跳转继续下一页；命令中的 `-L` 自动跟随。
任务完成才返回「采集完成」，失败返回 HTTP 错误，`-f` 使宝塔命令返回非零退出码。
每次命令最多运行一小时、跟随一万次跳转；遇到网络中断或命令时限，下次执行继续未完成任务。
同源同窗口已有任务时继续原任务；并发请求由任务锁保护，避免同一页同时执行。

旧 `route=cron` 命令仍只登记任务，不会自行采集，请重新复制新命令替换旧配置。
已有 Docker worker 可继续使用，与 curl 共用分页进度；后台「继续采集」每次处理最多 20 页。
任务进度存入 KV，清理已完成历史任务时同步回收，不需要修改数据库表结构。

视频和文章采集取页失败时，队列重试最多三次后标记失败；空列表且合法的
pagecount=0 视为正常无更新。手动分页接口保留原有错误展示。
文章定时采集的新增、补全、分类关联或计数写入失败时回滚当前页，保留断点供重试，
不会跳过失败页或把未写入的内容误报为采集完成。

Docker 中程序代码归 root 所有，PHP 用户仅能写 data、runtime、upload、
plugins、template。在线升级不能改写核心文件，核心升级应重建镜像。
安装配置写入 data，不要求 core/config 可写。

模板和插件使用独立命名卷，重建容器会保留安装内容。升级内置模板或插件时，
需要另外备份并更新对应卷内的文件，镜像中的新副本不会覆盖已有卷。
从旧版容器升级前，应先备份其 template 和 plugins 中的自定义内容并迁入新卷；
命名卷首次初始化只能复制新镜像内置内容，无法找回已删除旧容器中的自定义文件。
不要使用 `docker compose down -v` 升级，避免删除数据库和站点数据。

启动脚本通过 Git 属性和镜像内换行规范化兼容 Windows 检出。PHP 8.5 已内置
OPcache 时跳过重复安装，较早的基础镜像仍按需编译。
