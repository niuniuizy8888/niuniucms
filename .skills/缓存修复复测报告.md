# 缓存专项修复和复测报告

日期：2026-10-29。代码基线：6f36573。环境：Docker、PHP 8.5.12、MySQL 8.0。

## 修复内容

1. KV 写入、删除成功后同时清理请求内 memo 和共享缓存；共享未命中直接回库，避免旧 memo 重新污染共享缓存。合法的 false、0、空字符串和空数组保留原值。设置、网站命名空间 memo 也同步失效；写失败不发布候选值。
2. 当前缓存驱动接口无法返回权威剩余 TTL，缓存读命中只回填请求内层，不再提升到 APCu、Redis 等持久热层。即使同一对象曾记录 TTL，下层值也可能已被并发请求改写，因此不使用旧本地 TTL 延寿。新回源数据仍写入各层，使用秒级绝对截止时间扣除已消耗寿命；旧缓存格式可直接读取。
3. 每次内容变更都生成新的整页缓存版本，取消可能漏掉最后一次变更的两秒节流。
4. 统计快照记录原始截止时间；普通读取不保存，只有 runtime_set 标记变更后才按剩余 TTL 保存。过期快照不再发布，旧版无截止时间的快照会重算。
5. 内容单行读取统一走可失效的缓存入口，移除额外函数静态副本，更新和删除能立即作用于同请求后续读取。

为正确区分 KV 数据库失败与合法零行结果，QueryBuilder 的 REPLACE、DELETE 执行失败返回 false。

- 真实数据库与内容场景 11 项通过：只读事务中 KV 写入和删除失败均返回 false，数据库、共享缓存、memo 保持原值；文章和视频更新、删除后立即读取正确。
- 跨 PHP 进程读取 KV 得到新值；两秒内的第二次内容变更成功推进版本；统计保存后的 expiry 保持有限，未变为 0。

## 升级注意事项与范围

其他站点升级后也应在后台清理一次数据缓存和编译缓存，清除旧版本可能已经回填的陈旧值。

缓存读命中不再提升到持久热层，是对现有驱动接口的保守处理，可能降低故障恢复后上层预热速度；正常写入和新回源仍会填充各层，请求内 memo 继续避免重复查询。

当前实际启用 StaticCache 和 MySQL。Redis、Memcached、APCu 的多层编排采用隔离替身测试，未在本轮连接真实服务或做长时间压力测试。StaticCache 忽略请求内 TTL 的既有边界未作为这五项问题的一部分修改。
