# 开发规范

## 1. 基本原则

- 先看现有链路，再改代码
- 优先复用 Service、Repository、QueryBuilder
- 代码改完后同步更新相关文档与更新记录

## 2. 安全与输出

- 模板输出默认按裸输出看待
- 回显、接口、采集入库文本都要按上下文显式转义
- 写操作保持管理员门禁、`safe_token` 和审计日志

## 3. SQL 与数据访问

- 新 SQL 优先走 `RepositoryFactory`、`QueryBuilder`
- 列清单尽量显式写出，不要滥用 `SELECT *`
- 避免循环内查询
- 新增字段、索引、表结构时，同时补安装脚本和存量迁移说明

## 4. 缓存与日志

- 不手改 `runtime/cache/` 产物
- 不直接删运行时状态文件
- 排障先看 `runtime/log/`
- 大量、敏感或调试类日志要收敛，不要扩大线上日志体积

## 5. 配置与环境

- `config.php` 为主配置，`database.php` 为可选覆盖层
- `domain.php` 允许保留脱敏空模板
- 文档、注释、脚本不写宿主绝对路径

## 6. 插件与模板

- 插件视为受信代码，但仍应保持最小改动面
- 优先用 hook、设置页、独立资源，不要覆盖核心文件做主流程
- 模板和后台视图改动后要做一次真实渲染验证

## 7. 文档规则

- 文档统一放 `.skills/`
- 公开仓库只保留有复用价值的说明
- 过程稿、取证稿、重复说明不长期保留

## 8. 验证最低要求

- PHP 文件至少执行一次 `php -l`
- 涉及页面时至少验证一次页面或接口链路
- 涉及日志、安装、商店、采集时要检查对应错误通道
